# 热建CMS（RejianCMS）产品介绍  
> 热建企业CMS V2.0 正式版

---

## 一、产品定位

**热建CMS（RejianCMS）** 是一套基于 **CodeIgniter 4** 自研的模块化内容管理系统，为国内共享虚拟主机环境设计。

它不追求大而全的堆砌，而是把扩展能力做进底座——钩子中心、模块系统、插件机制、万能表单、编译式标签引擎与积木式页面装配，全部属于内核级基础设施，而非外挂组件。因此实现新需求时，无论加功能、改页面还是接系统，都不需要触碰框架核心目录。

> **一句话说明**：  
> 一套纯 PHP 实现、内核不改一行即可持续扩展的内容管理系统，最普通的虚拟主机也能稳定承载。

## 二、传统建站的困局与热建CMS的解法

### 常见的五道坎

- **改不动**：加一个功能就得改核心代码，系统一升级，之前的改动全部推倒重来  
- **贵**：插件生态被平台方掌握，想定制先谈授权费，商用还要看协议脸色  
- **装不上**：动辄要求独立服务器、Redis 扩展、命令行权限，共享虚拟主机根本跑不起来  
- **扛不住**：前台全靠动态渲染，访问量一上来数据库先撑不住  
- **扩不了**：想再做第二个站点、第二套语言，就得再买一套程序、再养一份数据  

### 热建CMS的对应解法

| 困局 | 解法 |
|---|---|
| 改动侵入核心 | 钩子中心 + 模块 + 插件三层扩展体系，核心目录一行不改即可挂载功能 |
| 授权与版权成本 | 全部代码开源无加密，依赖均为宽松开源协议，免费商用、无水印、无强制开源 |
| 环境门槛高 | 纯 PHP 实现，仅依赖默认开启扩展，Web 引导安装，上传即用 |
| 动态性能瓶颈 | 静态化优先，可静态化的页面全部输出 HTML 文件 |
| 单站扩展受限 | 单套程序支持多站点站群与多语言，一台虚拟主机即可承接多站点运营 |

## 三、四项自研内核能力

这四项能力决定了系统能被扩展成什么样，它们是写进底座的基础设施。

### 1. 三层扩展体系（HOOK · MODULE · PLUGIN）

- **钩子中心**：以事件总线与过滤器构成，钩子点与监听器持久化存储，支持优先级排序与监听器启停管理；插件停用时自动解绑其全部监听器  
- **模块系统**：依靠 PSR-4 命名空间自动发现，模块自带的数据表、路由、事件、过滤器与后台菜单零配置生效  
- **插件系统**：以清单文件声明元信息与生命周期，安装、启用、停用、卸载、升级、依赖检查全部在后台完成。官方内置幻灯片、广告、敏感词、关键词内链四款插件  

### 2. 编译式标签引擎（COMPILE · CACHE · TAG）

- 模板仅首次解析，编译为纯 PHP 缓存文件后直接执行；模板、标签库或内容更新时自动失效重编译  
- 内置 `arclist`、`pagelist`、`each`、`if`、`nav`、`site`、`field` 等标签，覆盖绝大多数数据调用场景；模块与插件可注册自定义标签  
- 配合 Markdown 渲染与站内标签混排，文章正文可直接调用内容列表、广告位等页面构件  

### 3. 三层模板与主题体系（DB · PHP · HTML）

- **数据库模板**：首页、列表页、详情页、个人主页可由数据库模板接管，后台编辑并即时预览，设为当前即生效  
- **PHP 主题**：电脑端与手机端主题独立，支持复制派生、在线修改与按页面类型的可视化预览  
- **HTML 主题**：以 `themes/` 目录规范组织（`theme.json` + 页面模板 + 布局），后台一键切换、代码编辑、iframe 实时预览；停用即回退 PHP 主题渲染  

### 4. 积木装配与静态化（BUILDER · STATIC · SEO）

- 页面即区块树，拖拽即可增删排序；逐块渲染、逐块缓存  
- 一键或增量生成纯静态 HTML，静态文件优先返回，内容变更时定向更新受影响的静态页  
- 同步生成站点地图并提供搜索引擎推送开关，输出结构化数据与规范链接

## 五、技术架构

系统采用五层结构，自上而下逐层收敛，扩展能力集中在应用模块层，稳定性由框架设施层保证。

| 层级 | 名称 | 职责 |
|---|---|---|
| L1 | 展示层 | PC 与移动端自适应模板、HTML 主题、翻页阅读器、区块树渲染结果 |
| L2 | 静态与缓存层 | 纯静态 HTML 输出、编译后的模板缓存、标签结果缓存、配置与权限的文件缓存 |
| L3 | 应用模块层 | 内容、会员、投稿、支付、电子杂志、评论、表单、通知、搜索、推荐、专题、多语言、站群等模块 |
| L4 | 扩展内核层（自研） | 钩子中心、模块与插件管理器、标签引擎、模板主题引擎、RBAC 权限、Markdown 渲染、一键排版、媒体上传、安装与迁移 |
| L5 | 框架与设施层 | CodeIgniter 4 的路由、控制器、模型、视图、验证、事件、过滤器与文件缓存；MySQL 与本地文件存储 |

### 三条设计红线

1. 模块与插件一律不得修改框架核心目录，全部能力经钩子、服务与视图组件接入  
2. 不引入需要单独编译安装的 PHP 扩展，缓存与队列均由文件系统承担  
3. 可静态化的页面优先输出 HTML，动态接口只负责交互与权限判定

## 六、部署与运行要求

所有条目均面向国内共享虚拟主机的通行环境设计，不含需要单独申请或编译的条件。

| 项目 | 要求 | 说明 |
|---|---|---|
| PHP | 8.2 及以上（推荐 8.2 / 8.3） | 现代虚拟主机普遍已支持 |
| 数据库 | MySQL 5.7+ 或 8.0，InnoDB，utf8mb4 | 推荐 MySQL 8.0 |
| 必需扩展 | pdo_mysql、mbstring、gd、curl、intl、fileinfo | 均为 PHP 默认开启项 |
| 缓存组件 | 纯文件缓存，不需要 Redis 或 Memcached | 消除主机扩展依赖 |
| 安装方式 | Web 引导安装，依赖预打包，无需 Composer 命令行 | 上传即可开始安装 |
| 上传能力 | 图片 / 视频 / PDF 上传，白名单与大小限制 | 随机文件名存储，无需修改 php.ini |
| 可写目录 | 仅 writable 与 public/uploads | 上传目录禁止脚本执行 |
| 伪静态 | Apache 自动写入规则，Nginx 提供可复制配置 | 含静态文件优先返回 |
| 第三方组件 | StPageFlip、PDF.js、qrcode-generator、思源字体等全部预打包 | 不依赖外部 CDN 亦可运行 |

### 安装流程

上传程序后直接访问域名，进入安装向导：  
**环境检测 → 数据库配置 → 自动建表 → 创建管理员**  
安装完成后向导自动锁定，避免重复安装。

### 升级方式

覆盖程序文件后，在后台模块管理页按提示执行增量迁移，模块与插件数据不受影响。

## 九、常见问题

### 免费版本与商业授权有什么区别？

没有区别。程序本体与全部内置模块、插件均以 MIT 等宽松协议发布，允许闭源商用、允许二次开发、允许交付给客户，不强制开源业务代码，页面也不留存品牌水印。

### 共享虚拟主机真的能跑起来吗？

可以。系统不依赖 Redis、Memcached、WebSocket 与命令行权限，缓存由文件系统实现。安装通过网页向导完成，唯一需要手动设置的是 `writable` 与 `public/uploads` 两个目录的写权限。

### 电子杂志一定要用 PDF.js 前端直出吗？

前端直出的好处是不必在服务端安装 Imagick 或 Ghostscript，普通虚拟主机即可承载，同时保留排版还原度。阅读器为独立组件，后续也可扩展其他渲染模式。

### 模块和插件应该怎么选？

判断依据只有一条：**需不需要独立的后台菜单与数据表**。  
需要就写模块，例如电子杂志、投稿审稿；不需要，只是在既有流程上加一段逻辑，就写插件，例如关键词自动内链、敏感词过滤。

### 给现有站点加功能，会改到框架核心吗？

不会。所有扩展都通过钩子中心、服务容器、视图组件、模板标签与页面区块接入，框架核心目录保持原样。系统升级时可以直接覆盖文件，不必逐行比对差异。

### 前台模板可以自己改吗？

可以。数据库模板在后台可视化编辑与预览，PHP 主题可在线修改源文件，HTML 主题直接编辑 `themes/` 目录下的 `.html` 文件，三者互不冲突，改动即时生效。
